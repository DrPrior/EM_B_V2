API surface and cross-cutting concerns

Four routers, a singleton database driver, an in-memory session store, per-IP rate limiting, and a timing logger. Interactive docs are generated at http://localhost:8000/docs.

One text-search subtlety

GET /graph/search uses toStringOrNull rather than toString (graph.py:237). Chunk nodes carry a 2560-element embedding array; toString on an array raises, whereas toStringOrNull yields null and the CONTAINS simply evaluates falsey. Without it, every search over a populated graph would error.

Session management

Rate limiting

rate_limit.py:14 creates a single slowapi limiter keyed on the client address. It is attached to the app and paired with the library's 429 handler in main.py:87, then applied to both chat endpoints with @limiter.limit(chat_rate_limit).

The limit is passed as a callable, not a string. That is deliberate (rate_limit.py:17): it is evaluated per request, so changing settings.rate_limit_per_minute takes effect without reimporting the module — which is what lets tests tune it.

slowapi requires the parameter to be named request

Both decorated handlers take request: Request as their first argument even though neither body uses it. Remove or rename it and the decorator raises at startup.

Timing instrumentation

timing.py answers "where did the seconds go" without changing any public API. Two kinds of line are emitted to the em_b.timing logger, joined by a short session id.

Configuration

Everything tuneable is a field on Settings (config.py:5), a pydantic-settings model reading .env case-insensitively. The module-level settings instance is imported directly everywhere else.

GroupSettingsNotes
Ollama connection ollama_base_url, chat_model, embedding_model, chat_base_model, embedding_base_model The variant names and their base models must stay in lockstep with the FROM lines in the Modelfiles
Bootstrap timeouts ollama_startup_retries (5), ollama_startup_delay (3s), ollama_request_timeout (10s), ollama_pull_timeout (1800s) The pull timeout is generous because a cold host downloads ~10 GB

Two values are not in Settings — NEO4J_AUTH and DB_URI are read straight from the environment by connection.py:51, which raises a descriptive ValueError if either is missing or malformed.

Response models

Every route declares a response_model. Neo4j records are mapped into Pydantic models before leaving a handler — NodeResponse and SearchResponse live in models.py:10, while the chat-specific ChatRequest, Source, ChatResponse and HistoryResponse are colocated with their router at chat.py:24.

Source is worth a look: url and superseded_by are both nullable, and superseded_by is only populated when a SUPERSEDES edge was found — which is what drives the amber warning under a citation in the UI (app.js:88).

Tests

tests/unit/ holds one module per source module, plus tests/integration/test_live_stack.py which exercises a running stack. Run them inside the container so imports and paths match production: 

docker exec em_b_v2-api-1 pytest
docker exec em_b_v2-api-1 pytest tests/test_rag.py -v
docker exec em_b_v2-api-1 pytest -m unit
