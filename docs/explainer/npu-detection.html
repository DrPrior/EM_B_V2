Detecting the NPU without pretending Ollama can use it

Every Intel Meteor-Lake-and-newer laptop — including this one — now ships an NPU alongside its GPU. The desktop wizard already fingerprints the GPU to decide whether to unlock Intel iGPU offload. This change teaches it to notice the NPU too, and to be honest about what happens next: it's reported, not used.

Why there's no OLLAMA_NPU_ENABLE

OLLAMA_IGPU_ENABLE=1 works because Ollama's Vulkan backend already enumerates the Arc iGPU and just needs permission to use it. No such switch exists for NPUs — none of Ollama's inference backends have an NPU code path at all.

AcceleratorDetected byOllama backendThis app's behavior
NVIDIA CUDA Win32_VideoController name native used automatically
Apple Metal system_profiler native used automatically
Intel Arc / iGPU (Vulkan) Win32_VideoController name present, dropped by default OLLAMA_IGPU_ENABLE=1 set for Intel-only hosts
Intel NPU (AI Boost) / Apple Neural Engine Win32_PnPEntity name match / Apple Silicon check none reported in accel, no env var — nothing to enable

How the flag decision is made

classify() in gpu.js is pure — raw device names in, flags and the accel summary out — so it's unit-tested without spawning PowerShell. Only the GPU flags feed ollamaenv.resolveVars(); npu stops at the readout.

gpu.detect()
Win32_VideoController + Win32_PnPEntity name match, or system_profiler / arch on macOS
→
classify(names, npuNames, …)
pure — sets intel / nvidia / apple / intelArc / npu, builds the accel string
→
ollamaenv.resolveVars(gpuInfo)
intel && !nvidia && !apple → add OLLAMA_IGPU_ENABLE=1
GPU flags → env vars
Intel-only hosts get OLLAMA_VULKAN=1 / OLLAMA_IGPU_ENABLE=1 persisted and Ollama is restarted to pick them up.
npu flag → nowhere
resolveVars() never reads gpuInfo.npu. It only reaches the wizard log line and this page.
Detect, don't fake it. It would have been easy to add an OLLAMA_NPU_ENABLE constant next to INTEL_ACCEL and call it done — it just wouldn't have done anything. Stock Ollama's CUDA / ROCm / Metal / Vulkan backends have no NPU path; NPU-accelerated inference exists only in separate, unintegrated stacks (OpenVINO, ipex-llm's NPU mode, community forks like NoLlama). So the NPU is surfaced for visibility — in the wizard log and in docs/HYBRID_SETUP.md — and left alone. If Ollama ever grows an NPU backend, the hook is already named: resolveVars(), right next to INTEL_ACCEL.
