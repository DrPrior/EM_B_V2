The RAG query path

One question, traced from the browser's fetch to the last streamed token. Streaming and non-streaming chat share the entire retrieval path — they diverge only at the final Ollama call. Everything below happens in src/services/rag.py:111.

End to end

Step by step

  1. Resolve the session conversation_store.get_or_create(session_id) (session.py:30) returns a UUID and the prior history. An unknown or absent id silently mints a new session rather than erroring.
  2. Embed the question embeddings.py:8 POSTs to /api/embeddings. This is the one step that is not allowed to fail — an exception here becomes an HTTP 500 (rag.py:129).
  3. Vector search _VECTOR_QUERY (rag.py:69) asks the index for retrieval_top_k nearest chunks, then OPTIONAL MATCHes back up to the owning File and collects any File that SUPERSEDES it.
  4. Extract entities from the question The same extract_entities the enrichment pipeline uses (extract.py:75), now applied to the user's text. Concepts and organisation names are flattened into one list; legal references stay separate because they are matched against a different edge type.
  5. Graph traversal _GRAPH_QUERY (rag.py:80) finds chunks that MENTIONS a matching Concept/Organization or CITES a matching LegalReference — case-insensitively — then rescores each with vector.similarity.cosine() against the question vector and keeps the best few above the floor. This finds text the pure vector search missed because it phrases the idea differently.
  6. Merge and deduplicate Vector hits first, graph hits appended. See the funnel below.
  7. Assemble the prompt and call the model [system] + history + [user with context], then either generate_chat_response or generate_chat_stream (llm.py:48).

How results are merged

Tuning knobs

All four values live in config.py:85 and are overridable from .env: retrieval_top_k (5), vector_retrieval_min_score (0.75), graph_retrieval_min_score (0.78), graph_retrieval_limit (3). Raising the floors trades recall for precision; the graph floor is set higher than the vector floor on purpose, because entity-linked chunks arrive without the index's own ranking to vouch for them.

What the model actually receives

Streaming

stream_answer (rag.py:270) runs retrieval synchronously and returns a generator. That ordering is what lets the router emit a metadata event containing the sources before the first token exists — the UI can render the citation panel while the model is still thinking.

Two details in the streaming path worth flagging

History survives a disconnect. The token generator accumulates tokens in a list and stores the turn inside a finally (rag.py:298). Whether the client reads every token or closes the tab halfway, whatever was generated lands in the session history — so a follow-up question still has context.

The client must buffer partial events. SSE frames are separated by a blank line, and a network read can split one in half. app.js:153 splits on \n\n and pops the trailing fragment back into the buffer rather than trying to parse it.

From answer text to clickable citations

The model is instructed to cite as (Source: filename.pdf). Turning that into a link is purely a client-side concern:

  1. Each source carries a url built by rag.py:49, which strips settings.data_root off the stored filepath and percent-encodes the remainder into /files/<relative path>. Catalogue-only entries get a URL too — the endpoint just 404s.
  2. On the done event, app.js:100 builds a filename→url map from this response's sources and rewrites every (Source: …) in the raw markdown into a markdown link, handling comma-separated multi-citations.
  3. marked.parse renders it, and every resulting anchor is forced to target="_blank" rel="noopener".
  4. files.py:23 serves the file inline, with a path-traversal guard that rejects any resolved path outside data_root.
The files endpoint is unauthenticated by design

This build is meant to run on the user's own machine, so /files/… has no auth — the traversal guard at files.py:42 is the only control. Exposing port 8000 beyond localhost would expose the entire corpus.
